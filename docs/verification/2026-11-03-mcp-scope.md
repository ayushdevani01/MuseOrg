# Preserve configured MCP OAuth scopes

An MCP server's authentication challenge could replace a client's explicitly
configured scope with the server's broader advertised scope. This surfaced while
preparing the official Meta Ads MCP connection. The authorization redirect now
retains the configured scope before applying the existing optional offline-access
behavior. Clients without an explicit scope continue to use server discovery.

A deterministic regression reproduced the broader redirect before the change.
All focused OAuth tests pass after the fix, including configured scopes, refresh,
server binding and offline access. The API and worker builds and adapter type
check pass. A live authorization request now contains exactly the configured
read-only Ads scopes; no account grant was made as part of that check.

The broader connector test run also exposed an existing Windows path-separator
expectation in its credential-file test. That run is not reported as fully passing.
The assertion and its platform handling are outside this scope correction.

Authorization URL creation does not prove account eligibility or a successful tool
call. Those require the separate account grant and a real MCP read receipt.

Reference: [Meta Ads MCP setup](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-get-started).
