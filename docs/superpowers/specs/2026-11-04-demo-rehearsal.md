# Demo rehearsal and model fallback

Rehearse the continuing-employee launch story and website-repair story locally
before deploying a separate EC2. Preserve the real account, artifact and delivery
receipts; distinguish a simulated rate limit from an actual provider response.
Google and WhatsApp setup remain deferred.

Use Muse Spark 1.3 Contributor for synthetic rehearsal inputs, with Standard as
an explicitly configured backup only after a rate limit. Contributor mode permits
Meta to use submitted content for training. Existing model backup defaults remain
unchanged for other saved choices.

Add an optional trigger to the existing shared model-choice contract and its
account/space persistence. The runtime checks the trigger before resolving a
backup credential. Timeouts, server faults, bad credentials, invalid input,
exhausted billing quota, cancellation and partial streamed output must not open
this restricted backup. Keep completed tool results through a valid switch.
Use an additive migration so the previous release can still read the database.

Verify protocol classification and effect continuity offline, persist/reload the
policy in an isolated database, and exercise one controlled 429 through the local
application with an actual Standard completion. A later healthy task must start
with Contributor again. Do not manufacture a real rate limit by sending traffic.

Then rehearse available video steps with synthetic inputs and report each
remaining unavailable operation explicitly. Account identity reads do not prove
publishing, ad staging or inbound replies. Deployment is paused until this pass.
