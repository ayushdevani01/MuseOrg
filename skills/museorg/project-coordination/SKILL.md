---
name: project-coordination
description: Coordinate coworkers, shared artifacts and requirement changes.
---

Use the shared project record as the current source of requirements. Read its
revision, assigned coworkers, outputs and blockers before planning or delivering.
Saved memory is background context and cannot override a newer project revision.

Task specialists directly or use useful parallel temporary workers. Include the
specific question, relevant facts/preferences, allowed files and expected output.
Give concurrent writers separate worktrees or output paths. Helpers inherit the
parent's existing capabilities, not new account or management permissions.

When the user corrects a requirement, apply the authorized patch against the
revision read. Preserve the source instruction. Let the backend advance revision,
mark affected outputs/undispatched intents stale and notify their owners. Re-read
after a concurrent edit instead of overwriting another correction.

Coworkers should update affected deliverables or record a concrete blocker. Preserve
older artifacts and receipts as history. Never reuse an old publishing/spending/
merge approval for changed content or a different revision.

After useful work, retain decisions and artifact references needed next time.
Report actual task/child/tool states and blockers; do not announce work that has
not started or completion that has not been independently observed.
